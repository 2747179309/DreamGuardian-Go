# SO-ARM101 硬件通信与过流保护排查手册 (Hardware Troubleshooting & Recovery SOP)

> **适用场景**：当舵机指示灯常亮（供电正常），但运行 `check_power.py` 报错 `[FAIL] 12V 未通电 (电压 0.0V / 舵机无响应)` 或 `RuntimeError: Missing motor IDs` 时，请严格按照本手册进行排查与复位。

---

## 一、 为什么舵机灯亮着，却报“电压 0.0V / 舵机无响应”？

飞特 STS3215 舵机采用 **3 芯白色排线串联总线（Daisy-Chain）**，线序定义如下：
1. **红色 / 外侧**：`VCC (+12V)` 供电正极
2. **黑色 / 中间**：`GND` 电源负极与参考地
3. **黄色(或白色) / 另一侧**：`DATA` 半双工串行双向数据总线

### 核心机理剖析：
- **供电与通信是两路独立通道**：
  舵机板载 LED 灯亮，**仅代表 VCC 和 GND 接通**，说明 12V 电源已经供到了舵机内部芯片。
- **通信报 0.0V 的本质是 DATA 数据线没有返回任何响应（底层状态码 `comm = -6`，即 `RX_TIMEOUT` 接收超时）**。
- **导致通信超时的三个根本诱因**：
  1. **CH343 串口芯片浪涌假死（最常见）**：
     - 控制板上的 CH343 USB 转串口芯片是由**电脑 USB 接口（5V）单独供电**的。
     - 如果您**只拔插了 12V 电源，而没有拔掉电脑 USB 线**，CH343 芯片自始至终都没有真正断电！
     - 当重新插上 12V 电源的瞬间，插头常伴有微小的电火花或地线电平波动，CH343 芯片的半双工收发控制脚被瞬间浪涌锁死在保护状态（只发不收），导致发出的 Ping 指令进不去舵机，舵机数据也回不来。
  2. **1号舵机 3 芯白色排线虚接 / 拔电源时被碰松**：
     - 控制板上的 12V 圆头电源插座紧邻 3 芯白色舵机插座。在插拔 12V 电源线时，极易无意碰晃到旁边的白色插头。
     - 若白色插头的 `DATA` 针脚稍有松动，12V 与 GND 依然通电（灯全亮），但数据线断开，直接导致底座 1 号舵机以及串联在其后的全部 6 个舵机彻底失联。
  3. **机械臂落到底部硬限位卡死 / 过流锁存（OverEle）**：
     - 当机械臂断电下落时，2号大臂舵机（shoulder_lift）掉落到了极限物理位置 `pos = 828`（底座卡槽硬限位）。
     - 若关节被死死压在底座硬限位上，舵机上电发力时无法动弹，会瞬时触发飞特芯片内置的 **Over-Current（过流报警，代码 err=8）**，使舵机进入保护锁存状态。

## 二、 黄金复位 SOP（每次遇到此情况的标准 4 步法）

每当遇到通信断连或 0.0V 报错，请严格按照以下步骤操作，100% 可彻底恢复：

### 步骤 1：同时拔掉双线（冷启动断电）
- **拔掉机械臂板载的 12V DC 圆头电源插头**；
- **拔掉连接电脑的 USB 数据线**。
- ⚠️ **必须两条线全部拔掉，等待 5 秒钟**（让舵机电容完全放电，同时让电脑释放 CH343 驱动句柄）。

### 步骤 2：检查并插紧 3 芯白色排线
- 用手检查并用力**按紧控制板上的 3 芯白色舵机插头**；
- 顺着排线检查插在 **1 号底座舵机两端** 的白色插头，确保卡扣插紧、无虚接。

### 步骤 3：用手将机械臂扶至“自然悬空姿态”
- 不要让机械臂死死趴在桌面上或压在底座卡槽硬止挡上；
- 用手轻轻托起大臂和小臂，使其处于半空中微屈的自然姿态，让 2 号和 3 号舵机离开极限死区。

### 步骤 4：按正确顺序重新接线通电
1. **先插上 12V 独立电源线**：观察从臂舵机指示灯亮起，且大臂处于悬空不受卡滞状态；
2. **再插上电脑 USB 数据线**：电脑将重新识别并初始化 CH343 芯片（COM5 重新建立干净的通信链路）。

## 三、 如何测试与验证？

### 测试方法 A：单次快速测试
在激活的环境中运行：
```powershell
python check_power.py
```
**正常输出标志**：
```text
=================================================================
[SO-ARM101 Hardware Power & Servo Status Check]
当前系统识别到的全部串口: ['COM3', 'COM4', 'COM5']
=================================================================
  [PASS 正常] 端口 COM5   : 供电正常 (12.3V) | 全部 6 个舵机在线就绪
         ↳ 在线舵机: [1, 2, 3, 4, 5, 6]
=================================================================
>>> 机械臂 12V 供电正常，通信通畅，可立即启动模型推理！
=================================================================
```

### 测试方法 B：动态实时监控模式（强烈推荐）
边插拔线缆边观察状态：
```powershell
python check_power.py --monitor
```
> **效果**：终端会以每秒 1 次的频率持续刷新。当您按紧线缆或重新插好 USB 时，屏幕会即时从 `[FAIL]` 跳变为绿色的 `[PASS 正常]`，清晰直观。

## 四、 恢复出厂配置指令（备用）

若怀疑舵机内部过流阈值异常，可在通信恢复后执行以下一键重置脚本：
```powershell
python reset_servo_registers.py
```
> 该脚本会自动将 1~5 号大关节舵机的最大扭矩恢复为 1000（100% 满功率），解除过流人为限制，确保机械臂具备充沛的抗重力抬升力道。
